# teum 기획 요약 (개발 참고용)

CLAUDE.md에서 분리한 기획 내용이다. 원본은 기획서 수정본(2026-11-10)이며, 바뀌면 이 파일을 먼저 고친다.

## 처리 흐름과 방법

입력: 전방 영상(블랙박스·휴대폰), 후방 영상(2채널 블랙박스, 선택), 내 속도(휴대폰 GPS, 없으면 수동 입력). 속도를 모르면 안전거리 기준은 건너뛰고 TTC·끼어들기로만 경고한다.

동작 모드:
- **영상 파일 분석 (기본):** 녹화 영상을 올리면 전체 기능으로 분석하고, 아찔한 순간을 앞뒤 5초 클립으로 저장한다.
- **실시간 (휴대폰):** 핵심 기능(거리·TTC·브레이크등·차선)만. 서버는 가장 최근 프레임만 처리하고 결과(JSON)만 돌려보낸다. 아찔한 순간은 수치와 경고 시점 이후 영상만 저장한다.
- 분석 코드(1~4단계)는 두 모드에서 똑같이 쓴다.

| 단계 | 기능 | 방법 |
| --- | --- | --- |
| 1 탐지 | 차·이륜차 찾기 (전방·후방) | 본넷을 잘라낸 뒤 YOLO로 차량과 motorcycle 검출 |
| 2 차선·앞차 | 차선 인식, 차선 유지 보조 | 사전학습 차선 모델 / OpenCV. 차선이 안 보이면 "차선 인식 불가" + 기본 차선 영역 |
| 2 차선·앞차 | 앞차 정하기 | 내 차선에서 가장 가까운 차(이륜차 포함) |
| 3 신호 읽기 | 브레이크등 인식 | 직접 학습한 YOLO, 앞차 박스 안 켜짐/꺼짐 2클래스 |
| 3 신호 읽기 | 방향지시등 인식 | 학습 없음. 옆 차 박스 좌우 끝의 주황색 밝기가 1초에 1~2번 깜빡이면 방향지시등. 주간·가까운 옆 차로 범위 한정 |
| 4 거리·위험 | 거리 | 핀홀 공식: 거리 = 초점거리 × 실제 폭 ÷ 박스 폭 (승용차 1.8m, 이륜차 0.8m) |
| 4 거리·위험 | TTC | 최근 약 0.7초의 1/박스 폭을 촬영 시각에 대해 직선으로 맞추고, 직선이 0이 되는 데 남은 시간 (TTC = -a/b). 내 속도 없이 계산 |
| 4 거리·위험 | 끼어들기 | 옆 차 바퀴 위치가 일정 시간(초) 안에 내 차선 쪽으로 다가와 경계를 넘으면 (프레임 수가 아니라 시간 기준) |
| 4 거리·위험 | 뒷차 확인 | 후방 영상의 뒷차에 같은 방식으로 거리·TTC (3차, 후방 영상 확보 시) |
| 5 표시·기록 | 경고 표시 | 박스·차선·거리·내 속도·경고 색과 소리 (WebSocket → React) |
| 5 표시·기록 | 아찔한 순간 기록 | 영상 파일 모드: 앞뒤 5초 클립, 실시간: 경고 시점 이후 영상 + 거리·TTC·시간·위치 저장 (FastAPI, PostgreSQL) |

**경고 단계**

| 단계 | 조건 | 화면 |
| --- | --- | --- |
| 안전 | 아래 조건에 해당하지 않음 | 기본 |
| 주의 | 안전거리(내 속도 × 2초) 부족, 또는 앞차 브레이크등 켜짐 + 거리 감소 중 | 노란색 |
| 경고 | TTC 3초 이하 | 주황색 + 경고음 |
| 위험 | TTC 1.5초 이하 | 빨간색 + 강한 경고음 |

- 상향: 끼어들기 감지, 또는 브레이크등 켜짐 + 거리 감소 시 한 단계 올린다.
- 예고: 옆 차 방향지시등이 내 차선 쪽으로 켜지면 실제 진입 전에 "끼어들기 예고"를 표시한다.
- 추가 경고: 차선 이탈(차선 중앙에서 일정 비율 이상 벗어나거나 선을 밟음), 뒷차 급접근(후방 TTC 3초 이하).
- 깜빡임 방지: 단계를 올릴 때는 즉시, 내릴 때는 짧게 기다렸다가 내린다.
- 아찔한 순간: "경고" 이상이거나 TTC 1.5초 이하이면 자동 기록한다.
- TTC를 두 프레임의 거리 차이로 구하지 않는다. 박스 떨림이 그대로 TTC 오차가 된다.
- TTC 3초 근거: NHTSA 전방충돌경고 시험 기준(2.0~2.4초) + 운전자 반응시간(평균 1.62초, Emami 2019) + 급제동·평활화 지연.

**개발 우선순위:** 1차(~11.13, 중간발표): 영상 파일 모드에서 탐지·거리·TTC·기본 경고, 브레이크등 1차 모델, 차선 이탈 경고, 아찔한 순간 저장·목록 → 2차(11.19~23): 브레이크등 개선·규칙, 차선 기준 끼어들기, 이륜차, 방향지시등 예고, 실시간 모드, 성능 평가 → 3차(여유 시): 뒷차 확인. 1차가 끝나기 전에 2차 기능을 시작하지 않는다.

**범위 밖 (요청이 없으면 추가하지 않음):** 블랙박스 화면 속도 글자 읽기(OCR), 방향지시등 학습 모델, 운전 습관 리포트, 앞차 출발 알림·음성 경고, 위험 구간 지도, 사고 영상 분석, 시내 도로·보행자 대응. 모두 향후 확장이다.

## 역할

| 담당 | 맡는 일 | 중간발표 책임 | 리뷰 |
| --- | --- | --- | --- |
| 성아영 | 브레이크등 인식 모델(데이터·라벨링·Colab 학습·평가), 경고 판단(브레이크등·차선 이탈·뒷차 통합), 뒷차 확인 | 브레이크등 인식 + 경고 규칙 | 모델: 최상준 / 판단·뒷차: 장혜민 |
| 장혜민 | 차선 인식 + 차선 유지 보조(카메라 중앙 보정), 차선 기준 끼어들기, 이륜차 감지 | 차선 유지 보조 | 최상준 |
| 최상준 | 아찔한 순간 기록(클립 저장·DB·API), 앱 화면(주행·영상 분석·아찔한 순간 목록·설정), 성능 평가 | 아찔한 순간 기록 + 목록 화면 | 성아영 |

- 다 같이: 테스트 영상 수집(브레이크등·끼어들기·차선 이탈·이륜차 장면 각자 2~3개), 통합 테스트·시연 영상(11.24~25), 발표 자료.

## 미정 (팀 결정 필요)

브레이크등 모델과 깜빡이 라벨은 기획서와 라벨링 가이드가 다르다. 모델 담당(성아영)이 정하면 이 표를 하나로 고친다.

| 항목 | 기획서 (현재 기준) | 라벨링 가이드 |
| --- | --- | --- |
| 모델 구조 | 앞차 박스 안 켜짐/꺼짐 2클래스 YOLO | YOLO 차 검출 → 차를 잘라 상태 분류 |
| 학습 데이터 | Roboflow 2개 (CC BY 4.0) + 직접 라벨링 | TLD 일부 (약 15만 장 중 1~2만 장) + 직접 라벨링 |
| 깜빡이 | 학습 없음, 밝기 패턴, 영상만 수집 | turn 속성을 라벨링해 다음 단계용으로 모아 둠 |
